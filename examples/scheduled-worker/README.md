# Scheduled Worker Example (@Cron in wasmCloud)

This example demonstrates **deployment-aware `@Cron` execution** in `@di-framework` and wasmCloud, resolving GitHub Issue #403.

## Key Concepts

1. **Application-Facing API**:
   Services use standard `@Cron(schedule, options)` annotations.
   ```typescript
   @Injectable()
   export class MaintenanceService {
     @Component(DatabaseRepository)
     public db!: DatabaseRepository;

     @Component(AuditLogger)
     public audit!: AuditLogger;

     @Cron('0 2 * * *', {
       name: 'nightly-prune',
       description: 'Purges expired database session records nightly',
       allowConcurrent: false,
     })
     public async purgeExpiredSessions(): Promise<MaintenanceReport> {
       const summary = await this.db.deleteExpiredRecords();
       this.audit.recordAction('prune_expired_sessions', { count: summary.deletedCount });
       return { job: 'nightly-prune', pruned: summary.deletedCount };
     }
   }
   ```

2. **Scheduled-Only Workloads (No HTTP Ingress)**:
   In `di-framework.config.json`, setting `"ingress": false` marks the application as scheduled-only:
   - No HTTP ingress port (e.g. port 80) is exposed.
   - Kubernetes `Service` manifests are suppressed.
   - `wasi:http/handler` export is omitted from the WIT world.

3. **External Scheduler Dispatch vs. In-Process Execution**:
   - In **standalone/local** execution, in-process timers run automatically via `setInterval` and cron expression calculation.
   - In **external** execution mode (`DI_CRON_MODE="external"`), automatic in-component timers are disabled to prevent duplicate executions across replicas or clock drift.
   - The CLI plugin automatically generates Kubernetes `batch/v1` `CronJob` manifests configured to trigger each discovered job externally.

4. **Private Invocation Interface**:
   External schedulers dispatch to the private invocation interface generated by `@di-framework/cli-plugin-wasmcloud`. The invocation interface:
   - Resolves the owning service through the DI container (`container.resolve(...)`).
   - Injects all required dependencies (`@Component`, `@Inject`).
   - Enforces concurrency constraints (`allowConcurrent: false` prevents overlapping runs).
   - Awaits asynchronous execution and reports structured completion or failure metrics.

5. **Local Manual Job Invocation Without Delays**:
   For testing and operational maintenance, scheduled jobs can be invoked immediately without waiting for timers:
   ```typescript
   const result = await container.invokeCronJob('nightly-prune');
   console.log(result.success, result.durationMs);
   ```
